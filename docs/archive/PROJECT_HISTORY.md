## Retired documentation groups

- **Batch reports:** older version-specific batch notes and test reports are reduced to summaries when retired; release-level details remain in `CHANGELOG.md` and the retained previous/current release handoff.
- **Coverage reports:** historical counts are not current product state. Use the latest retained coverage report only as the baseline for its release; `MASTER_STATUS.md` carries current totals.
- **Lexical/source notes:** older IPA and vocabulary source work used Cambridge Dictionary pronunciation references, normalized to the project's US IPA convention. New source-backed changes must record sources in the current release batch; do not recreate a permanent one-file-per-version source folder.
- **TOEIC format references:** ETS, IIBC and official TOEIC Korea sources are used only for public blueprint metadata (200 questions, Listening/Reading timing and Part distribution). No official questions, passages or audio are copied.
- **Old platform/architecture proposals:** superseded experiments outside the current GitHub Pages + PWA architecture are historical only and must not re-enter active implementation without an explicit architecture decision.

## Archive rules

1. Keep only the immediately previous and current release-specific batch/report/update-note files in the active docs tree.
2. When a release is retired, append one compact entry per retired file here, including version, title, old path and up to three key facts.
3. Never archive or delete canonical data, app code, `assets/`, user-owned photographs, PWA shell resources, patches or local learner data.
4. Do not create independent master/roadmap/compatibility/design-system summaries. Update the single corresponding document.
